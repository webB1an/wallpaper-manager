# 上传队列恢复

当前部署为单 API 进程。任务记录保存于 MySQL，Redis 负责执行调度。

- 每分钟检查一次超过两分钟未更新的任务；Redis 查询失败时不修改任务。
- 新任务使用任务 ID 作为唯一队列 ID，并完整保存批次、网盘账号及频道账号选择。
- 自动恢复仅面向从未开始执行、没有 AI/网盘/上架痕迹且本地原文件存在的上传任务。恢复后仍遵守空闲窗口；全部有手动标题的任务不等待 AI 时段。
- 旧版批量任务缺少账号信息、缺失资源或已有处理痕迹时，标记失败并解释原因，需人工核对后重新处理。
- 重启前中断的旧版运行任务不会自动重放，避免重复发帖；没有阶段记录的历史自动发帖也会标记中断。新版自动发帖按下面的检查点规则恢复。当前进程仍在运行的长任务不会按固定时长误判失败。
- 执行前重新检查空闲时段；已经开始的任务不在窗口结束时强制中断。修改窗口不会立即提前已有延迟任务，但执行时会使用最新设置。
- 数据库原子认领阻止同一任务重复执行；不承诺不同任务提交相同资源、或外部平台请求成功但响应丢失时的全局 exactly-once。

## 新版自动发帖检查点

- 检查点放在 MySQL Task.payload 中，与壁纸入库和来源去重记录在同一事务提交。队列每轮查询最多 100 条待核对记录，Redis 按 100 个任务分段读取，兼容旧数字 job ID。
- 阶段为：桥接下载、保存入库、AI 审核、准备网盘上传、网盘上传中、准备发帖、发帖中、已取得发帖成功回执。
- 下载使用 `storage/tmp-bridge` 的文件及元信息，不再将整个文件缓存在内存。跨调用、跨进程重启恢复时核对 URL、强 ETag、长度与 Range；完成的本地文件直接复用，范围不一致则停止并清除损坏缓存。
- 静态回传总预算为 15 分钟，动态为 60 分钟（含本次调用的续传重试）；连续 60 秒无数据触发连接中断检测，最多重试 3 次。
- 新版任务重启后仅自动继续安全检查点；明确失败的任务由管理端任务队列“从失败阶段继续”按钮触发。一个进程内只能执行一个自动发帖任务，恢复入口在数据库读取前即预留执行权。
- 网盘上传中或发帖中没有持久化回执时，禁止自动重放，需人工核对。明确“暂无权限”失败可回到准备发帖阶段，调整账号后继续；超时不是明确拒绝，不能据此重发。
- 已取得并保存发帖成功回执时，只补齐本地状态和清理，不再发送帖子。仍不承诺外部请求成功、但回执保存前进程崩溃的全局 exactly-once。
- 可恢复失败暂存文件最多保留 24 小时（以任务最后更新为准）；未传完的桥接文件仍受桥接端约 2 小时 TTL 限制，不承诺 24 小时内远端一定可用。完成本地副本后不再依赖远端。
- 过期后禁用恢复、删除临时原文件，保留资源记录和封面。清理失败记录 cleanupPending，后续对账重试。成功或不可恢复失败立即清理本地桥接缓存。
- 本次增加 Task 查询索引，部署需要执行新增 Prisma migration；不批量重放历史失败任务，也不改变小程序接口格式。

## 上传临时文件

小程序管理员上传和批次完成入口先执行权限 Guard，再进入文件接收流程。这里沿用现有 openid 白名单，不代表已经完成独立登录凭证改造。

临时目录清理在服务启动和之后每 10 分钟运行，清除超过 24 小时的普通文件，跳过当前活动文件和目录，不递归进入其他路径。上传业务处理失败仍即时清除本次临时文件。

## Redis 运维

队列恢复不能代替 Redis 安全配置。上线诊断会提示队列记录不一致，以及全网卡监听且保护模式关闭的风险。

若 Redis 被其他项目共用，不要直接清库或修改全局 ACL/监听地址。先盘点调用方，再选择隔离实例或为各应用设置独立账号及权限，禁止业务账号执行 FLUSHALL/FLUSHDB，限制 6379 的网络访问。单独选择 Redis 数据库编号不能抵御 FLUSHALL。

建议为队列实例启用持久化并备份，禁止内存淘汰队列数据。持久化本身不能阻止合法命令执行清库。

本地回归：`npx tsx --tsconfig apps/api/tsconfig.json --test apps/api/src/modules/admin/queue-recovery.test.ts`。测试只使用模拟队列与数据库，不上传、不发帖。
