# WallMuse 文章与公众号合集

此模块由桌面 WallMuse 使用，沿用管理员登录、静态来源、DeepSeek 和网盘账号。代码开发完成不代表生产已启用。

## 使用流程

新建 1–18 张文章（自动来源或最多三个已启用静态来源）→ 空闲时段下载与去重 → AI 识别审核与网盘准备 → 收齐指定数量 → 随机选首图 → 按首图定主题并排列其余图片 → 文案生成 → 待发布中预览、编辑、导出封面 → 正文复制成功进入历史 → 手动同步小程序合集。

所有 WallMuse AI 请求，包括只改标题，均使用北京时间空闲窗口。旧服务关闭 `processIdleEnabled` 不会让 WallMuse 绕过窗口。窗口为空/无效时禁止生成；已开始的网络传输可以完成，后续 AI 步骤重新检查窗口。修改窗口后等待任务在下一轮按新配置判断。手工编辑、复制和导出无需等待。

生成、保存和复制均不会上架小程序。同步仅使用准确的已复制版本，事务内一次性更新素材和创建固定合集，不发送腾讯频道帖子。重复请求返回同一合集；同步后文章不可再编辑或更新合集。`collectionOnly` 将这些壁纸隔离于发现、标签、首页轮播及相关推荐。小程序首页搜索下方固定显示“公众号合集”，暂无合集时进入后显示空状态，请求失败时显示重试，无新增底部 tab；合集内进入原壁纸详情/获取原图流程。

## 上线步骤

1. 先按既有部署流程备份数据库与整个 `storage`，停新任务并等待进行中的工作。保持现有安全检查。
2. 部署增量迁移 `20260912143000_wallmuse_articles`，运行 `npm run prisma:deploy` 和 `npm run prisma:generate`。迁移只加表/字段/索引，不删除原记录。新版公共列表与旧来源共享认领需要新字段，因此即使功能关闭也必须先迁移。
3. 更新 API，在管理端「系统设置」开启「启用 WallMuse 文章与公众号合集」并保存（默认关闭，无需修改环境变量或重启）；沿用 `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL`，可选 `DEEPSEEK_TEXT_MODEL`。不替换现有密钥。至少一个可用默认网盘账号、已启用静态来源、有效空闲窗口、WallPost 桥接必须就绪。
4. 桌面设置用原管理员账号登录（凭据仅保留在当前会话）；确认能力接口显示真实来源、空闲窗口和小程序 AppID。浏览器开发端允许 `127.0.0.1:1420` / `localhost:1420`，桌面允许固定 Tauri origins，所有文章接口仍需 Bearer 管理员认证。
5. 编译并按既有流程发布小程序新包，新增 `pages/collections/collections` 与 `pages/collection/collection`。旧包不会自动出现合集入口。
6. 在空闲窗口创建小批真实任务，核对去重、网盘账号、每张图片与文案。复制后在公众号粘贴并手机预览，再手动同步小程序。这里的回执只证明正文已复制，不证明公众号发布成功。

## 恢复与数据

- `WallMuseJob` 保留步骤和检查点；只有失败任务可手动继续，取消不删除已入库/已上传的素材。新建、重新生成、复制回执和合集均具有幂等边界。
- 新旧自动来源共用 `SourceIntakeService`，先取得来源租约；源 ID 和文件 SHA-256 分别去重。来源别名与 Wallpaper 在同一事务创建，冲突不留下孤立壁纸；提交结果未知时先读库核对再清理本地文件。
- 新旧上传共用存储传输租约；WallMuse 固定创建时选中的网盘账号，中途默认账号变化不会改写归属。已上传、已分享的阶段不重做。共享租约忙时任务稍后继续，不能绕过锁。
- 新任务上传结果未知时先查原账号；分享结果未知时不重发。桌面任务行“核对网盘结果”显示原文件和账号。核对确实没完成后可确认重做该阶段；已有分享则补记原链接。服务比较原账号、素材和阶段并记录核对动作，不直接在请求事务中调用网盘。
- 本地历史和复制回执存放 IndexedDB。网络故障后可在历史中补记；只连接原服务才能补记，不将凭据持久化。旧复制回执不会倒退已采用的新复制版本。
- 私有文章 JPEG 存放 `storage/wallmuse/article-images`，由受鉴权接口提供；封面和原图沿用原目录。备份必须包含私有目录。管理员清理已发布原图会跳过被文章引用的资源；人工删除文件后只报缺失，不换图。
- 旧记录优先按原 `WallpaperSource` 排除。历史已清除原图的记录没有可计算文件哈希，不能宣称已完成历史跨来源内容去重。可运行下面的本地原图回填，默认仅读取，不从网盘批量回源、不合并旧记录。

```sh
# 在 API 的实际工作目录执行；storage-root 必须指向其真实 public 目录。
npx tsx --tsconfig tsconfig.json src/scripts/backfill-wallpaper-hashes.ts --limit=100 --storage-root=/path/to/storage/public
# 核对 dry-run 输出后，可加 --apply 写入哈希；下一批使用 --after=输出的nextCursor。
```

在管理端系统设置关闭 WallMuse：下一轮调度停止处理新步骤，已开始的步骤允许完成；公开合集内容为空，首页入口保留并显示空状态，既有管理员功能继续。不要回滚删除文章表或已引用素材。

## 验证范围

单元/回归覆盖时间边界、复制与保存区分、旧回执、版本冲突、重复同步、租约排他、取消和未知网盘结果。API/小程序需通过类型检查与构建。上线前仍须实际 MySQL 迁移、真实桥接/AI/网盘、公众号粘贴以及微信开发者工具/真机检查；本地替身测试不等于这些验收。

## 自动主题与原图保留（2026-09-14）

- 风格偏好可留空。收齐指定数量后，在这批图片中随机选择首图；批次和首图在 AI 调用前持久化，任务重试不会重新随机。一次策划调用根据首图确定主题并排列其余图片，全部保留，不再因主题不同丢弃或补采。文案按每组真实内容自然过渡，不能声称全部图片都是首图的题材。
- 选择 18 张就准备 18 张合格且不近似的图片；仅对来源失败、重复或审核不通过补采，仍有最多 54 次采集尝试上限。来源编号和 SHA-256 去重之外，本篇图片的感知哈希去重已提前到 AI 识图之前。
- 旧主题筛选任务的 theme_pending/off_theme 图片可复用既有分析和网盘检查点；即使预算耗尽，手动继续也会优先利用这些已有素材，不直接重新下载。AI 策划和文案仍遵循原有空闲时段。
- 后台每小时检查一批到期素材。文章引用的原图在任务完成后保留至少 7 天；未引用候选在任务完成/取消后保留至少 3 天。运行、等待、失败待恢复的任务均不清理。
- ready 素材删除服务器原图前，必须核对所有已记录网盘的原账号、共享完成检查点、有效链接记录和远程文件身份/大小；网盘查询失败或文件不匹配就保留。文章排版 JPEG、封面、历史版本和网盘文件保留。
- rejected/off_theme/near_duplicate 素材在无任何历史版本引用且过期后删除服务器原图、封面及文章 JPEG，保留数据库去重记录。共享素材、非 WallMuse 文件、未完成任务、路径不匹配或符号链接均不清理。
- 清理持有任务及存储传输租约，再读状态；日志记录素材编号、释放字节数和保留数量。无数据库迁移，不清空现有文章，不删除网盘文件。失败任务长期不处理仍会占用空间，需完成或取消后才进入保留期。
